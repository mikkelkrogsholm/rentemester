View decrypts the strict existing default encrypted pool of zero through ten unique canonical case-sensitive codes. It returns the remaining pool without changing it, and appends a mfa_backup_codes_viewed event to canonical append-only workspace_audit. Audit uses entity_type native_mfa_backup_management_v1, entity_id as the canonical JSON tuple [subject,sessionId,auditKeyVersion], actor user:<subject> and created_at from sampled trusted time. Regeneration validates the old pool before replacement, generates ten fresh unique unbiased default codes and encrypts with the current configured key/fresh OS nonce. Exact old-ciphertext CAS and a mfa_backup_codes_regenerated workspace_audit event commit together. Old codes immediately cease to authenticate; the old pool, factor secret/verified flag, login failures/lock, user flags, existing sessions and TOTP replay state otherwise remain unchanged. Existing pending enrolled-login challenges bind current factor/identity and may use only the new current pool after regeneration. No setup/challenge authority, automatic session rotation or TOTP change is granted. A prior account login lock is not a shortcut to a new session and is not reset by management.

Sensitive code lists retain non-Debug/non-Clone/non-Serde zeroizing owned buffers. Return codes only after known commit, including view's accepted audit. Malformed pool/key/clock/config or late SQL failure rolls back the complete operation, with no disclosure or false accepted audit; confirmed rollback determines handle reuse. Lost/unknown regeneration is reconciled with another fully authenticated view or an explicit subsequent regeneration, not a blind replay.
