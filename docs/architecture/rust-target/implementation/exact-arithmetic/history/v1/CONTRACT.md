# Exact amount, currency and FX values

Continue R09 with shared pure decimal arithmetic used by Money, positive six-decimal FxRate and canonical Currency codes. Retain existing Money raw parse behavior/resource limits (ASCII decimal/exponent, <=2048 input bytes, exponent-400..400, half-away-from-zero quantization). Extract its grammar into one private decimal implementation; no new dependency or floating point in the domain. BigInt operations never wrap; arbitrary-precision results remain exact. This is not a new configured business maximum or ISO currency registry.

Money.multiply_decimal parses both RAW operands and rounds the product only once to two decimals. Money.percent applies an already quantized amount and a percent rounded to two-decimal basis points, then rounds the ratio once. FxRate.parse rounds to six decimals and requires the resulting rate to be strictly positive; apply uses an already two-decimal amount times the six-decimal rate, with one final half-away round to cents. These deliberately different quantization stages match their existing consumers. Negative money/percent values are allowed; zero or negative FX rates refuse. Private signed rounded division must handle all signs, half cases and zero denominator without wrapping. Reuse that primitive across quantization/product/percent/FX operations.

Currency.parse accepts exactly three uppercase ASCII letters, including configured/synthetic codes; it does not default, trim, Unicode-normalize or certify ISO registry membership. Legacy adapters still own normalizeCurrency and configured currency eligibility. Money is a two-decimal value (DKK øre, or existing two-decimal foreign amount); currency/source quote identity is explicit caller context. FxRate.apply alone does not authorize a conversion or prove a journal's FX evidence.

Wire serialization is exact string money with two decimals, rate with six, currency with three letters. Add explicit canonical Money/FxRate constructors for strict serde deserialization: reject numeric JSON, exponent notation, leading plus/zeroes, negative zero, noncanonical scale, whitespace and any text whose parsed canonical output differs. Raw quantizing constructors remain separate and retain existing behavior. No JSON floating-point authority. Parse errors are typed invalid_input, invalid_rate or invalid_currency; canonical and rate positivity refusals must not yield partial values.

Acceptance: preserve existing Money/read/report/hash behavior; native fixed cases exercise signed halves, raw-product versus prequantized FX, signed percent, min positive rates, huge integers, parser bounds, all division signs/zero and strict canonical serde. Independent Python Decimal fixed expectations (no product imports) plus actual TypeScript money helper observations cover rounding/exponents, raw products, percentage basis points, rounded rates and FX stages. Ordinary number-domain results must match; numeric bridge precision, binary intermediate FX differences and native typed/canonical admission are separately frozen with actual source outputs. Do not normalize discrepancies away. Verify domain dependency/direct-I/O boundaries, complete previous suites, scoped GDD readiness and independent review. No persisted hash/wire format, TypeScript source, production data, writer authority, complete posting/FX policy, interest/legal rules, report/UI migration or broad R09/epic completion is delivered by this scope.
