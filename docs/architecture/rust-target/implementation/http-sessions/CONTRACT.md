# Native HTTP own-session management and React account menu

Expose the existing native `session_control` operations through canonical GET `/api/auth/list-sessions` and POST `/api/auth/revoke-session`, `/api/auth/revoke-other-sessions`, `/api/auth/revoke-sessions`. The trusted owner explicitly injects one optional handler that maps typed proof/operation to the admitted native application transaction. Without it these endpoints return404; HEAD on list always returns405 and never dispatches or charges rate. The Rust router never forwards these paths to Better Auth. Independently running legacy endpoints/writers must be drained and exclusively routed before real enablement; this library does not perform that deployment. No default data opener, workspace path, caller subject or writer grant comes from HTTP.

Every dispatched operation requires a strict signed current-session cookie from the configured workspace/profile. Malformed/bare/duplicate named credentials, duplicate Cookie headers, pending-factor credentials and mixed Authorization/service credentials refuse. GET allows missing Origin for same-origin browser reads, requires configured Host, checks present Origin and fetch-site, and accepts no query or body. POST requires matching Origin/Host, same-origin-compatible fetch-site and JSON without content encoding or query. Revoke-one accepts exactly a JSON object with one nonblank non-control UTF-8 `sessionId` of at most4096 bytes, never a bearer `token`, array, duplicate field or user ID. Other revokes accept an empty body or empty JSON object only. All read bodies are bounded8192 bytes/2seconds. Shared runtime capacity is four blocking workers whose permits remain held inside blocking execution. List has a direct-peer10/minute bucket; all three revokes share a separate direct-peer10/minute bucket, unaffected by forwarded headers or target rotation. Existing bounded process rate state is shared with identity/recovery. Proxy/distributed admission and production listener/TLS/shutdown/logging remain separate qualification work.

The native application retains canonical control checks, a BEGIN IMMEDIATE writer, one trusted sampled clock, fresh current session younger than ten minutes, verified email, enabled/verified MFA and active workspace access. No local credential/password is needed for own-session management. Listing is an audited writer operation, not a cached read. Return active owned metadata sorted createdAt descending then ID ascending, with only id/createdAt/expiresAt/current/ipAddress/userAgent; no token or arbitrary row fields. Storage validates all owned rows before expiry filtering and bounds rows/display/serialization; HTTP also refuses serialization over1MiB. List failure/unknown commit withholds the list and success response. Confirmed operational rollback is atomic; audit persistence remains unconfirmed after an unknown commit. Exact validation, authority and transactional effects remain defined by [the native session contract](../session-control/CONTRACT.md).

Revoke-one deletes only the owned ID. Foreign and missing targets have identical known-success no-op responses. Revoke-others deletes all owned rows except current, including expired rows; revoke-all deletes all owned rows including current/expired. Real deletions produce existing lifecycle triggers and accepted native audit, without changing other subjects, credentials or factors. Known success alone returns200 `{"status":true}`. Only known successful all/current-one returns configured native clear cookies, never arbitrary handler headers. Other-one, others and listing set no cookie. Native not-committed invalid credentials maps to401 `INVALID_CREDENTIALS`; operational/validation/unknown commit/panic maps to503 `AUTH_UNCONFIRMED` with no listing, clear header or claimed deletion. No automatic transaction retry is added. Reconciliation requires current authenticated observations, never resurrecting deleted rows.

This intentionally corrects installed Better Auth's token-bearing listing and bearer-target revoke contract. The retained React account menu accepts either native rows (explicit boolean current, no token) or the existing legacy rows (token, no current), refuses ambiguous/mixed/invalid rows and never guesses between contracts. Native one-revoke sends only sessionId through the existing client's raw same-origin fetch; legacy one-revoke continues its existing token contract until cutover. Display uses generic browser labels and creation time, never raw tokens/user-agent. Native current identifies the current device even when session context lacks its ID. Confirmation remains required for one/all revokes. Explicit list/one/all requests disable retries. Both one and all must receive data.status exactly true before removing a row or clearing the shell. Error, transport loss, false/empty/null ACK keeps the displayed state with an explicit unconfirmed message; it does not assert that the server session remains active. Closing/reopening the list or explicitly logging in reconciles; no automatic replay or fallback is triggered.

Acceptance uses real native HTTP processes, canonical synthetic controls in WAL/DELETE, installed source-signed cookies, owned/foreign/missing/expired facts, precise native audit/lifecycle observations, strict pre-dispatch refusals, freshness/current-access refusal, malformed owned metadata, real DELETE commit-busy for list and revoke-all, shared direct-peer revoke rate and absent-handler refusal. Socket unit tests cover GET bodies, duplicate Cookie headers and invalid/unknown/panic outcomes on all four routes. React tests qualify native/legacy selection, confirmation, truthful ACK/unknown handling and explicit retry0, while an installed-client probe checks actual request encoding and false-ACK behavior. No real data, live dual-writer admission, deployed browser session flow, OAuth/cache/trusted-device/provider parity, full account/security interface, CLI/MCP/GPUI distribution, cutover or whole epic completion is claimed.
