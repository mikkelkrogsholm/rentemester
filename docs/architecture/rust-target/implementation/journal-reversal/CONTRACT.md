# Native authenticated manual journal reversal

Implement append-only manual reversal on current canonical admitted company connections, under the existing current-human control→company writer fence and ledger.post permission. No product opener, HTTP/CLI/MCP writer, invoice repair authority, service quota admission or physical lifetime authority is introduced. Full platform goal and outer transport policy/backup/confirmation gates remain open.

The strict request contains only original entry ID, reversal date and reason. Current actor and compiled rule version are trusted separately; business input cannot supply lines, historical/VAT policy, repair authorization, document/bank references or attribution. Original ID must be positive JavaScript-safe. Original and ordered joined lines are read inside the company writer. Preserve source refusal precedence: missing original, original itself a reversal, protected issued_invoice/credit_note document, prior reversal, no lines, then current validation. All issued invoices and credit notes are protected even without domain links; no generic repair bypass.

Build reversal from persisted original evidence. Swap exact debit/credit, retain raw VAT including whitespace/empty versus NULL, and retain header document/bank/FX metadata. Nonempty original text becomes REVERSAL: plus raw text; NULL/empty becomes REVERSAL of original entry number. Header text uses ECMAScript-trimmed reason. Only exact persisted rentemester-import-postings with NULL document grants missing-document historical exemption and retains import program; otherwise current runtime program is used. Every reversal allows uncoded VAT control while all other active account, balance, VAT code, document/bank, period, future-date and FX validation remains enabled. These privileges are internal, never deserialized request flags; ordinary manual validation remains unchanged.

Allocate a new fiscal number/identity, hash and retention using the established posting numeric/schema/sequence helpers. Insert new status reversed and reversal_of_entry_id referencing the original; never update original headers/lines or invoice/domain records. Write journal_reverse audit with current actor and source message. Do not resolve/reopen bank exceptions. Canonical reversal-shape, unique and append-only SQL guards remain enabled. Malformed or unsafe persisted numeric/identity metadata and malformed current tail hash refuse with whole rollback; newly stored hash/readback is checked, without introducing a full prior/original audit-integrity gate absent from source; legacy FX ambiguity remains an explicit adapter refusal.

Application optionally composes JournalReverse durable receipt under stable current human principal, authorizing before replay. Every business/storage failure aborts the whole transaction. Success/receipt is released after known commit only; uncertainty withholds result and retires the affected handle. Native typed fingerprint is its own protocol, without arbitrary legacy transport fingerprint equivalence.

Acceptance uses actual unchanged TypeScript in-current reversal against independent synthetic current ledgers, comparing result/rules, full typed effects, hash/number/retention/audit and original preservation. Cover ordinary and historical/uncoded VAT positives, raw VAT/text, protected invoice negatives, period/account/bank validation, repeat reversal and source-number constraints. Real WAL/DELETE fault/death/concurrent same-original/replay/unknown-commit evidence must qualify atomicity. This contract is implementation scope, not a claim that any test or full issue already passes.
