# Descriptor-bound workspace layout

Outcome: consume the existing cooperative WorkspaceLease and bind one existing registered company's physical layout through no-follow descriptor-relative opens. Retain the root lease, manifest, control directory/file, selected company directory/data directory/file. All six descendant identities remain pinned until Drop. Source paths are workspace.json, .rentemester/workspace-control.sqlite and <slug>/data/ledger.sqlite. Never create, migrate, recover, open SQLite connections or write source files. No product writer is enabled.

Configuration supplies an explicit nonblank workspace key and exact safe company slug. The key is a runtime association, not a newly invented persistent logical identity: the current v1 manifest contains no stable workspace UUID. Parse a bounded1MiB UTF8 JSON manifest with exact version1, typed fields, unique safe company slugs and exact Boolean archived. Reject missing/malformed/oversize/duplicate/unknown fields and invalid entries rather than legacy String/Boolean coercions. Names and createdAt are bounded nonblank non-control metadata; createdAt is not interpreted as an authority timestamp. Require exact registration and a nonarchived selected company. Archived entries remain legal for other companies. No unlisted-company adoption or default manifest.

All path segments below the already held root use openat with NOFOLLOW/CLOEXEC/NONBLOCK, and DIRECTORY for directories. Final files must be regular single-link files; reject symlinks, hardlinks, FIFOs, devices, missing paths and control/ledger aliasing. Require every component on the root device and all component identities distinct, including the root; descendant mounts/aliases on other devices are unsupported. Keep file descriptors private, non-Clone and unexposed. Binding errors have fixed codes and never include source bytes or credentials. Require an unchanged root before and after binding; compare the manifest descriptor identity and SHA256 bytes again before returning. Existing candidate-filesystem limitations of WorkspaceLease remain.

ensure_current reopens the exact descriptor-relative paths, compares held and current device/inode identities and required type/link count, and checks exact manifest identity/content. Root loss or any layout change invalidates the object permanently; restoration cannot revive it. Retain the root lock and old descriptors until Drop. Changes in ledger/control contents or file size are permitted: those are transaction-owned data, not namespace changes. Namespace observation is not an atomic fence against a local OS actor replacing/restoring files between observations. Legitimate future namespace/manifest operations must obey the same lifetime ownership protocol; current unpatched legacy entrypoints still do not.

Expose only bound workspace key, selected slug and ensure_current. Do not expose descriptors or turn recorded device/inode pairs into write authority. This does not prove an arbitrary rusqlite Connection points at the held file; path equality or matching before/after stat is insufficient evidence about an already-open SQLite handle. A later owned connection/VFS admission boundary must solve that before trusted writers. Stable logical identity/clone lineage, runtime generation, all legacy mutation enrollment, IPC, storage/platform qualification, actual authenticated posting and full R03/R12/R13 acceptance remain pending.

Acceptance: synthetic canonical layouts bind without changing names/bytes; wrong keys/slugs/manifest types/duplicates/archives and every unsafe path level refuse; revalidation detects root/manifest/control/company/data/ledger replacement, in-place manifest changes and hardlink introduction, stays invalid after restoration and retains ownership until Drop. Ordinary ledger bytes/size changes do not invalidate physical binding. Real processes prove a held layout excludes a second root lease and process death releases it. Existing lease checks plus native format/Clippy/runtime tests pass; independent review inspects the descriptor and manifest boundaries. This is physical layout observation, not database-handle qualification or completed writer admission.
