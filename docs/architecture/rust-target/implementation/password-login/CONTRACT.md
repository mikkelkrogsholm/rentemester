# Native password-to-MFA transaction

Outcome: compose native password crypto with the current canonical workspace-control account rows, without Bun/Node. Internal synchronous application operation only: an admitted, caller-owned connection is reused across a short read transaction, unlocked KDF, and BEGIN IMMEDIATE revalidation. The runtime must already own the workspace lifetime and bind the actual SQLite handle; physical handle admission is still unqualified. No public endpoint, production connection, session issuer or complete authentication provider is enabled.

Input: email and password, each at most4096 UTF8 bytes. Email lookup accepts the installed Zod practical ASCII email grammar, folds ASCII case and compares stored email exactly. Control characters (including a final newline accepted by JavaScript dollar anchoring) refuse explicitly. Password uses the current Unicode17 canonical scrypt primitive and its existing limits. Historical unversioned normalization profiles still need inventory/mapping/re-enrollment. Unknown user, absent/empty/noncanonical/wrong password, missing or disabled workspace access, or changed candidate return opaque invalid_credentials. Full current schema/history/integrity admission remains mandatory; malformed control facts are invalid_control, never raw SQL diagnostics. Timing equality across database branches is not claimed.

Candidate selection joins user to account with exact userId, providerId='credential', issuer='local:credential', accountId=user.id and email. Multiple qualifying rows fail closed instead of selecting an arbitrary first row. Capture user ID, email, strict emailVerified and nullable twoFactorEnabled flags, user updatedAt, account ID/updatedAt/password, and latest workspace access event ID/role. IDs and timestamps are bounded nonblank strings without control characters. Only a valid activate event for member/workspace_owner is eligible; the latest disable excludes the user. Password storage buffers zeroize on drop; no Debug/Clone/Serde or secret error formatting. Database library internals and input buffers remain outside erasure claims.

End the initial read transaction before one real or dummy KDF. Then begin the same connection's control writer transaction and repeat schema/integrity admission and exact candidate selection. Require equality of all captured fields, including latest access event ID. A password reset, credential replacement/retarget, email change, email verification/MFA change or access revoke/reactivate visible across these reads refuses. This compares current rows and declared update timestamps, not an unforgeable historical epoch: restoring every field can evade change detection. During the successful continuation the writer lock prevents competing SQLite writers from committing changes until its commit/rollback.

An unverified email never invokes the continuation. A verified eligible candidate invokes exactly one trusted synchronous continuation with subject and NextFactor::Challenge or NextFactor::Enrollment. Neither route asserts MFA completion, grants company access or creates a session. The callback may implement a future pending-MFA persistence step on this same control transaction. Current tests persist only synthetic workspace_audit marker events. The callback must not issue sessions, external effects, SQL transaction escapes, detached work, or expose first-factor observations as reusable authority. This is trusted Rust orchestration, not a SQL sandbox.

Commit the continuation transaction, returning its value only on known successful commit. Any earlier failure explicitly rolls back; failed rollback marks connection nonreusable. Any commit error is OutcomeUnknown and retires the connection; no retry or claimed completion. Callers must reconcile before retrying an unknown outcome. Require autocommit writable main, WAL/DELETE, FULL/EXTRA synchronous, foreign keys enabled, query_only off, and no attachments or temporary schema before beginning. Unsupported connections refuse without mutations. No filesystem or company DB is opened by this operation.

Acceptance: actual TypeScript workspace-control migrations and installed Better Auth account issuer/lookup/password functions provide synthetic fixtures and independent reference observations. Native process tests cover correct password/MFA and enrollment routing, wrong/missing/malformed credential, provider/issuer/accountId mismatches, strict flags/schema, email grammar, unverified/inactive access, known rollback and unchanged source state on refusal. Independent connections mutate after the initial read to demonstrate KDF runs without the control lock; stale candidates refuse after reset/email/MFA/access/credential changes. While continuation holds its writer lock, a competing revoke must be SQLITE_BUSY; after commit it succeeds. Preserve existing full Rust checks. No endpoint CSRF/origin/rate/concurrency, actual challenge/session/recovery lifecycle, OS or production cutover acceptance is claimed.
