## Parser, HEAD and representations

Native POST structs are derived Serde, `deny_unknown_fields`, without an outer object-only guard. Exact full positional arrays in declaration order therefore coexist with object input. All input fields are required; null is not optional. Native signed-i64/u32 bounds are distinct from SDK positive/safe integers, object-only discovery and SDK confirm/hash prevalidation. JSON body is bounded16KiB. Unknown and duplicate fields are refused; explicit false confirmation parses but storage refuses. GET queries are wholly forbidden, including empty `?`, rather than silently ignored. Scheduled GET does not inspect body or encoding; hosted GET requires actual empty body with a1-byte extraction bound and refuses content encoding.

Scheduled HEAD is **not** GET: it requires write-origin/cookie/catalog/query/content-type/body admission, then the last path segment has no write parser branch and returns404 `not_found` before worker permit or operation Owner dispatch. With ordinary missing JSON content type it returns400 instead. It never interprets an enable/dispatch body at those paths. Catalog selection itself can touch the already-held Owner; “before Owner dispatch” does not mean no catalog access. Hosted HEAD returns405 before endpoint proof/query/body/key lookup, with no handler-added Allow header. Every HEAD wire entity is zero bytes, including protocol middleware failures; refusal schemas are constructor JSON, not a HEAD response entity. No HEAD was called against a live ledger.

Product JSON headers are application/json and cache-control:no-store; outer defaults add nosniff. Protocol incompatibility is409 application/json with outer no-cache/nosniff. No Set-Cookie is produced here. There is no binary download even when dispatch persists an original PDF internally.

## Effects, recovery and authority

Enable records intent/installs extension, catch-up queues, skip resolves, pause/resume/cancel update consent. Consent/reconsent do not generate, post or send. Dispatch selects only current owner app-mode queued/normal-due unresolved occurrence at an exact reviewed planHash; active template/current permissions/backup/transfer and existing issuance/period/evidence guards survive. Issuance runs within a savepoint, stores immutable original evidence and generation identity, then appends terminal status. File publication can outlive a rolled-back SQL transaction; an unavailable response is not proof of no effect.

No HTTP request idempotency-key, TTL or tombstone contract is supported. Exact template/period claim and unique generation are natural dedup, not permission to repeat stale mutation bodies. A failed attempt is recorded/resolved, not automatically resent. Reconcile current list/plan/history stateHash, eventHash, generation documentId/invoiceNumber and original source evidence before an explicit subsequent decision. Missing readback under changed authority/company/source does not establish absence.

Restore overlays preserve generation/audit evidence and unresolved attempts while pausing consent, clearing live owner/queue and deactivating hosted binding. Historical owner/queue stay visible under restoreConsent, never become current grants. Explicit current-admin reconsent requires reviewed restore-bound planHash and rejects unresolved_attempt; it does not replay historical queued work. Hosted binding includes human security/access and service credential-generation anchors; revoked human/service cannot authorize fresh dispatch. Unknown in-flight delivery elsewhere remains auditable/unknown: reconciliation is not send; explicit reviewed retry is separate. This partition makes no SMTP/IMAP/provider approval claim.
