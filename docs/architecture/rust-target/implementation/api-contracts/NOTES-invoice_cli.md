## Parsing and producer boundaries

SDK descriptors are shape checks, not proof of native outputs. Its validator counts string UTF-8 bytes and ignores JSON Schema pattern/oneOf; receivables add explicit selector XOR. Native Serde-derived structs without an object guard accept positional arrays in full declaration order even with deny_unknown_fields. Local CLI object guards prevent submitting top-level tuples; `Serde*` definitions document the native distinction. Optional fields may be absent in object form but tuple slots are required (null for Option). Recognized duplicate struct fields fail native parsing; raw input bytes are not normalized before send. Original lifecycle has recursive duplicate detection, object guards and no-null validation. Original issue SDK schema is intentionally narrower than the native original producer; do not infer newly supported flags/fields from server allowances.

Native money outputs are JSON numbers in the legacy wire profile, not invented decimal strings. Nullable monetary reads, optional computed fields, customer defaults, original currency and DKK aggregates remain separate. PDF reads/preview validate MIME and signature then expose integer bytes in JSON, never raw stdout; original render only returns descriptor metadata. No local PDF write/open is promised.
