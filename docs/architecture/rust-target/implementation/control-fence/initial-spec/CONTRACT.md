# Human control-to-company transaction fence

This R04/R13 storage/application increment implements an internal synchronous transaction path over two caller-owned admitted SQLite connections. It does not open source paths or enable a product mutation endpoint. The full epic and identity-provider decision remain open.

The caller supplies a trusted provider-authenticated human session observation (workspace key, exact subject/session IDs, provider authentication readiness), a registered company selection bound to its workspace and slug, and the operation's statically chosen company permission. None of these observations implements Deserialize. A claimed actor, supplied role, held process lease or session-row ID alone is not authentication. The provider must already have verified credentials, session expiry and any required MFA/session assurance. Services/local identities require their own later adapters. Company registration/archive/path identity must remain fenced by the caller's lifetime/manifest admission; SQLite alone does not protect workspace.json.

Both connections must be initially autocommit, have no attached or temporary objects, foreign_keys ON and synchronous FULL/EXTRA. The runtime must bind distinct, stable physical/logical databases and enforce one global control-before-company lock order for all entrypoints. Existing TypeScript writes are not enrolled by this increment; originals remain forbidden until lifetime admission/cutover. The API rejects public/workspace permissions before any callback. It establishes control BEGIN IMMEDIATE, admits the complete current checksummed control schema/history and integrity/FKs, reads exact current user/session membership and latest workspace/company access by signed SQLite event ID (never timestamp), and evaluates the shared Rust policy. Missing/deleted or wrong-user session, missing/unready user, disabled workspace, revoked membership, archive or cross-scope observations deny without executing business work. Current control rows override supplied company membership; no client role is accepted.

Only after authorization does it establish company BEGIN IMMEDIATE. Trusted synchronous callback work uses that transaction, with no await, network, external effects, transaction-control SQL, connection close, other connections or control writes. Journal/evidence/rule/confirmation/backup checks and atomic receipts belong to the eventual callback/use case; this increment is not posting or idempotency completion. Callbacks are trusted Rust code, not sandboxed SQL. A detected manual callback commit/lost transaction yields an uncertain-outcome failure, never an ordinary refusal.

Success commits the company transaction before releasing the control lock by explicit rollback. SQLite control writers such as disable, revoke, exact session deletion and MFA invalidation can commit either before admission (then deny) or after the company commit, never between the protected observation and commit. Control is never deliberately written. Cleanup failure after a known company commit returns the committed value with control_reusable=false; it cannot be represented as a pre-commit failure. A company commit error or lost transaction reports outcome_unknown and requires retiring affected connections/recovery using the future durable receipt. Before any company commit attempt, callback/SQL/authorization failures explicitly roll back and report not_committed with per-connection reuse status; rollback failures require retirement. Panics/process death rely on SQLite rollback/lock release; a crash after ledger commit preserves the commit. Already allowed results and prior receipts never bypass new authorization.

Acceptance: actual canonical synthetic control stores plus isolated transaction-effect ledgers; current-row denial and full-width/latest-ID cases; exact permission and scope refusal; active/deferred transaction, attach/temp, disabled FK/durability and read-only admission refusal; successful company commit with no control data effects; business/SQL failure after sequence and companion writes rolls both back; callback transaction escape reports unknown. Barrier-driven separate processes prove revoke-first denial, revoke blocked while the fence is held, pre-commit killed/reaped child rollback and post-commit killed/reaped child preservation. Repeat over WAL and rollback journals where supported, preserving source/protected fixtures and all previous access-policy checks. Such effect ledgers prove transaction mechanics, not complete accounting schema/domain admission or hardware power-loss qualification. Final format, Clippy, targeted native/process suites and independent review must pass; GDD scoped readiness precedes implementation. No real company data may be used.
