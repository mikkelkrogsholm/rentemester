# Native enrolled TOTP login transaction

Outcome: compose the native password and MFA crypto into enrolled-user challenge issuance and atomic TOTP verification/session creation on an already admitted caller-owned canonical control connection. No HTTP listener or real workspace path is opened. Actual SQLite-handle/workspace lifetime admission, endpoint origin/rate/bounded blocking and production cutover remain mandatory before exposure. Unenrolled users get EnrollmentRequired after valid password, without a session or setup authority; actual enrollment, backup recovery, trusted devices and rememberMe variants remain pending.

Runtime explicitly supplies workspace-bound cookie signer/verifier, MFA decryption keyring, trusted Clock and safe nonnegative audit-key version. Native bearer/row IDs use 32 OS-random bytes, canonical base64url; challenge identifiers prefix 2fa-. Signed cookies retain the installed Better Auth names and HMAC-SHA256 secret STRING/standard-base 64/percent-encoding format. Secure profile emits Secure; both profiles emit Path=/, HttpOnly and SameSite=Lax. Challenge Max-Age 600 and session Max-Age 43200. Request verification retains bounded strict duplicate/secure-vs-development/service-header refusal. A session cookie never substitutes for the required signed MFA cookie. All bearer/cookie values omit Debug/Clone/Serde and owned new token/cookie buffers zeroize; broader input/library/compiler/allocator erasure is not claimed.

Begin uses the already verified password transaction: expensive KDF outside lock, exact current credential recheck inside BEGIN IMMEDIATE. Current verified email, active workspace access and enabled MFA are mandatory for a challenge. Exactly one verified twoFactor row must belong to the subject. Strict integer flags and bounded typed values fail closed; legacy NULL verified is not implicitly adopted. A current account lock refuses issuance. Write the source-compatible verification challenge and attempts rows, plus one native private context row, together; no temporary authenticated session is created. Native context binds the trusted workspace, current length-framed SHA256 credential/user/access fingerprint, MFA row/secret fingerprint and latest credential/email/MFA/session-deletion lifecycle event ID. These private verification fingerprints never enter audit, diagnostics or exported evidence. No native context means restart password login; foreign in-flight Better Auth challenges are not silently adopted.

Verify the signed challenge and current records under one control BEGIN IMMEDIATE. Require exactly one challenge/attempt/context record, canonical ISO UTC millisecond dates, created<=now<expires, positive TTL<=600000, equal creation/expiry across records, canonical count 0..4 and exact current native context. Recheck user/email/MFA/access/credential/factor and lifecycle revocation before decrypting or checking the code. Changes visible between issuance and verification refuse. Fingerprints compare current captured rows, not an unforgeable historical epoch for every possible restored field. Read the clock once while locked; admitted work crossing its deadline does not retroactively undo commit. Clock must leave room for a full 12-hour session within year 9999.

Each wrong/malformed/replayed TOTP code commits one challenge failure and one account failure, plus rejected telemetry, under the same lock. Burn all three pending records immediately on the fifth failure (a deliberate correction to source cleanup on the next attempt). Account budget spans fresh password challenges; tenth consecutive failure locks 15 minutes. No issuance or verification bypasses a future lockedUntil. At/after exact lock expiry, failure counting starts from 0. Missing/NULL account counter means 0; negative/oversized/malformed state refuses. Operational decryption/clock/SQL/admission failures roll back, do not spend attempts, and never become authentication success.

A correct code must return a TOTP counter greater than the last native accepted counter for that factor row. Store its monotonic replay record in the existing verification table under a native namespace, together with failure reset, deletion of challenge/attempt/context, a fresh canonical 12-hour session and accepted telemetry. The existing immutable session_created trigger is the authoritative session lifecycle event. Valid TOTP alone grants nothing before successful commit. Return a signed session cookie only after known commit; company access still resolves the exact current session under the existing authorization fence. Concurrent verifies serialize so one challenge/code cannot create two sessions. Persistent replay protection is a native correction; it is not enforced by a legacy writer, and restore/lineage/cutover qualification remains separate.

Known authentication refusals with committed attempt/audit effects are explicit Rejected outcomes, not rollback failures. Invalid context/admission and SQL errors return opaque fixed-code failures and explicitly roll back. Every commit error is OutcomeUnknown, retires the connection and withholds cookies; reconcile before retrying. Callback/SQL escape or external effects are not exposed by this use case. Existing connection preflight requires writable autocommit main, WAL/DELETE, FULL/EXTRA sync, foreign keys and no temp/attached schemas. Atomicity is one control DB only.
