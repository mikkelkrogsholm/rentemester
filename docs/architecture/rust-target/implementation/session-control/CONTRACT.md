# Native own-session listing and revocation

Implement internal List, SignOut, RevokeOne(sessionId), RevokeOthers and RevokeAll operations on an admitted control connection. Runtime injects only CookieVerifier, Clock and bounded audit key version, without requiring an MFA encryption keyring or password. Preflight connection readiness before any reusable refusal; accept only a session-kind proof from the same workspace, signer key and configured cookie profile. Service/pending proof and caller subject claims do not authorize these operations. All final observations, deletions, lifecycle triggers and accepted audit hold one BEGIN IMMEDIATE and one sampled trusted Clock. Canonical current control schema/history/integrity and ordered-event exhaustion guards remain mandatory.

List and revocation require exact current-token resolution, canonical unexpired twelve-hour-bounded session younger than ten minutes, current verified-email/MFA-enabled user, active member/owner workspace access and exactly one factor with strict verified=1. Do not require a local credential account, decrypt MFA data or refresh session age. No company privilege or target bearer is required. RevokeOne accepts a bounded nonempty non-control session ID and deletes only WHERE id/subject match; missing and foreign IDs have the same successful zero-deletion result. RevokeAll deletes all own rows, including current and expired; RevokeOthers atomically deletes every own row except current, including expired. These intentionally strengthen source authoritative-session-only revocation with freshness/current workspace/MFA gates, replace source bearer targets and make source active-only multi-delete others atomic and inclusive. No other user's session may be listed or deleted.

SignOut uses only runtime-bound proof and exact token row lookup/deletion, without expiry/freshness/access/MFA/factor/password gates. It handles expired or malformed timestamp cells and disabled users. Structural ID/subject ambiguity still refuses. Already missing rows return known-commit idempotent success without fabricated subject/audit. Unlike source's swallowed DB errors, a database failure is never reported as confirmed server revocation. A pure runtime helper can independently expire configured native session_token/session_data/dont_remember/two_factor cookies without claiming database success. Transactional output carries these clear headers only after known commit when SignOut/RevokeAll or RevokeOne-current removes the caller; no headers/data on failed/unknown commit. Chunked cache/account/OAuth-provider logout remains unqualified; current native profile issues no such state and source cookie cache is disabled.

List is an audited writer operation. Validate at most1000 total own rows before filtering, failing explicitly at1001 rather than returning a partial list. Each ID is bounded4096 non-control/nonblank bytes; timestamps are canonical UTC millisecond, created<=now, expires>created and lifetime<=12h. Invalid owned timestamps refuse even in expired rows. Return only active rows, sorted createdAt descending then ID bytewise ascending, with allowlisted id/createdAt/expiresAt/current/ipAddress/userAgent. IP and user-agent are nullable bounded non-control display strings (256/2048 bytes), never identity/authority. Bound total returned metadata to1MiB, never include tokens or arbitrary row fields. Revocation remains available for cleanup of an oversized/malformed listing. Source's token-bearing/unbounded listing is a deliberate native versioned contract correction, not a byte-compatible source response claim.

Every existing-row SignOut, List and revocation appends a distinct workspace_audit event (session_signed_out, session_listed, session_revoked, other_sessions_revoked, sessions_revoked), entity_type native_session_control_v1, entity_id canonical JSON [subject,currentSessionId,auditKeyVersion,targetIdOrNull,deletedCount], actor user:<subject>, created_at from sampled trusted time. No bearer, IP or user-agent enters this event. No schema mutation or unsupported login telemetry endpoint label is used. Missing/foreign RevokeOne is an authorized audited no-op. Canonical session_deleted triggers are the authoritative lifecycle evidence; each actual deletion advances native pending MFA's existing relevant lifecycle count and invalidates earlier login/enrollment contexts for that subject. No-op revokes with no deletion do not claim pending-ceremony invalidation. TOTP counters, factor secrets/backup pools/budgets, users, credentials and other subjects remain unchanged.

Known operational/validation failures roll back all writes and release no result/headers; confirmed rollback plus postflight determines handle reuse. Every commit error returns OutcomeUnknown, retires the handle and releases no listing/receipt/clear headers, without automatic retry or rollback assertion. The independent pure local-clear helper is not evidence of server deletion. Reconcile lost/unknown results by current token/session inspection, never by resurrecting rows or accepting cached provider responses. Revocation may not race past another admitted writer lock or resurrect deleted sessions. Repeated SignOut with an already-deleted valid proof is a no-op success; other operations need a still-current authorized session.

Acceptance uses actual canonical migrations, installed source session readers/logout/revocation/cookie attributes on separate synthetic copies, and independent native WAL/DELETE processes. Cover token-free stable bounded listing, no local credential requirement, nullable/display metadata, fresh/expiry/current-state/proof/target refusals, expired/disabled/malformed-time/missing logout, foreign-user protection, exact trigger/audit counts, pending MFA invalidation after real deletion, contention/revoke races and no new-session resurrection, complete late rollback, real DELETE commit-busy withholding and source/native interoperable revocation. Preserve all previous checks. No exposed HTTP/CLI/MCP/UI endpoint, physical SQLite-handle/workspace lifetime admission, source/live dual writers, restore lineage, remote OAuth/provider/cache/trusted-device flows, real data adoption, distribution/cutover or whole Rust epic completion is qualified.
