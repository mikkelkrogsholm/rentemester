# Actual SQLite main-handle identity

Outcome: compare the actual open SQLite main database descriptor with the control and ledger files retained by WorkspaceLayout. A pathname may be restored after SQLite opened a different inode; matching pathname observations cannot prove handle identity. This prerequisite advances persistent runtime admission. It grants no writer authority and does not complete R03/R12 or the platform epic.

Pin rusqlite 0.40.2 and libsqlite3-sys 0.38.2 through Cargo patches to complete vendored upstream snapshots. Retain upstream licenses, original per-file SHA256 and crates.io archive SHA256 in vendor/sqlite-provenance.json. Only four upstream files differ: rusqlite Cargo.toml, Cargo.toml.orig, src/lib.rs and bundled sqlite3/sqlite3.c. vendor/sqlite-identity.patch records the complete diff. The verifier rejects missing, extra, symlinked or changed snapshot files and mismatched patch hashes. These are application-specific dependency patches, not upstream APIs; workspace unsafe_code=forbid remains unchanged. Graphify excludes vendored upstream snapshots and indexes this contract and the runtime consumer.

The Unix VFS implements application opcode 0x524d0101 in unixFileControl. The caller supplies eight aligned initialized 64-bit words with magic 0x524d4944454e5431 and ABI version 1. After validating the header the VFS clears the full buffer, fstats its actual unixFile.h descriptor and requires a regular file. It returns magic/version/device/inode/mode/link-count and two zero reserved words. Invalid ABI is SQLITE_MISUSE, missing descriptor/nonregular file is SQLITE_NOTFOUND and fstat failure is SQLITE_IOERR_FSTAT. It does not stat a pathname, expose descriptors, alter SQLite locks, pager, journals or namespace operations. Other VFSes and the SQLCipher amalgamation do not implement the opcode.

With feature rentemester_identity, safe Connection::main_file_identity fixes the schema to main, holds the connection's internal borrow through synchronous file_control, owns the initialized stack output and verifies ABI header/reserved fields. It returns only integer metadata; no pointer or descriptor escapes. Non-OK status returns its own SQLite error code without trusting a stale connection error message. Memory databases or VFSes without the patch refuse; no pathname fallback. This safe boundary assumes trusted SQLite/VFS implementations, as do existing rusqlite FFI APIs. The pinned bundled default Unix VFS is the intended consumer; arbitrary loaded native extensions/VFSes are outside the trusted runtime profile.

WorkspaceLayout::ensure_connections first and last checks the retained layout and compares both actual main handles against the exact retained control/ledger device and inode. A current single link is required. Any mismatch or observation error permanently invalidates the layout; restoring names or supplying different handles cannot revive it. Read-only handles may match this physical observation: connection write mode, canonical schema/logical identity, actor authorization and writer admission remain separate required checks.

Database-name revalidation must not open or close ordinary file descriptors for either SQLite inode. Closing such a descriptor can cancel another SQLite connection's POSIX locks held by the same process. ensure_current now uses descriptor-relative no-follow statat from retained parent directories for all regular names, including the manifest; retained-file metadata uses fstat. Manifest bytes are reread with read_at on the retained file, without cloning/opening/closing it. A manifest replaced with a hardlink to a live database must refuse without releasing that database lock. Only directory components are reopened with DIRECTORY/NOFOLLOW. bind must occur before opening SQLite connections, and the eventual owning runtime must close every SQLite handle before dropping the retained layout descriptors. This increment does not introduce that owning runtime or permit arbitrary lifetime order to serve writes.

Acceptance uses synthetic persistent files on the current macOS candidate filesystem and Linux ARM64 container tmpfs. The Linux run compiles the same locked source with Rust 1.94.1 and passes all 16 local lease/layout tests (3 subprocess helpers ignored outside explicit parent invocation); its image digest and source hashes are recorded separately. WAL and DELETE journal modes preserve physical identity through real transactions and reopening. A deterministic ABA swaps each database name, opens a different real SQLite file, and restores the original name before observation: the old pathname oracle passes and actual-handle comparison refuses stickily. Swapped connections, memory, added hardlinks and unlinked handles refuse. A real independent child process must remain SQLITE_BUSY before and after both ensure_current and ensure_connections while the parent holds BEGIN IMMEDIATE on either database in both journal modes; it acquires only after rollback. A further child-process test replaces the manifest with a hardlink to each live database and proves refusal still preserves its lock. These tests prevent the confirmed pre-fix accidental lock-release defect and its refused-manifest-alias variant from returning. Existing layout tests retain namespace-change and manifest checks.

Limits: an identity snapshot does not prevent replacement after checking, qualify sidecar namespace lifetime, exclude an unenrolled same-UID legacy writer, prove fsync/power-loss durability, or admit existing user workspaces. A persistent owner still needs enforced namespace ownership, safe initialization/reopen/bootstrap, schema and logical IDs, proper close/drain/restore order, authenticated transports and OS/deployment qualification. Actual cross-UID denial, Linux host-storage and deployment qualification remain required. Container compilation/behavior is verified; no Windows/Linux deployment qualification is claimed here. Unsupported WorkspaceLayout platforms expose the same method and return UnsupportedPlatform. Tests never use real business data.

References: SQLite's [file_control contract](https://www.sqlite.org/c3ref/file_control.html) routes a named database to its VFS xFileControl; [standard opcodes](https://www.sqlite.org/c3ref/c_fcntl_begin_atomic_write.html) document the existing file-pointer and moved-name observations. The new opcode is local to the pinned patch and its exact ABI above.
