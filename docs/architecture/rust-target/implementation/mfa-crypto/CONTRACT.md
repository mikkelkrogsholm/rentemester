# Native existing MFA cryptography

Outcome: native issuance/decryption of existing encrypted MFA values plus source-compatible six-digit TOTP verification and random enrollment secret generation. This removes the Node/Bun crypto/OTP dependency needed by the pending-MFA transaction, not the remaining challenge/session/enrollment/recovery provider. No DB, principal, HTTP endpoint, MFA completion, replay guard or product writer is enabled by a cryptographic match. Source: installed Better Auth1.7.1 crypto and two-factor plugin, @better-auth/utils OTP/HMAC, and Rentemester's injected-secret policy.

A trusted caller explicitly injects an ordered keyring of1–16 unique nonnegative JavaScript-safe integer versions, first active, plus optional explicit legacy secret. Each key string is canonical unpadded base64url encoding of at least32 bytes, bounded to4096 ASCII bytes. Original entropy is not recoverable or proved by encoding. Encryption derives a32-byte key as SHA256 of the secret STRING's UTF8 bytes, not decoded entropy. XChaCha20-Poly1305 uses a fresh OS-random24-byte nonce, empty additional data, and stores lowercase hex of nonce||ciphertext||16-byte tag. New values always use $ba$VERSION$HEX with the first configured version. Decode selects exactly that declared version; historical keys decrypt only. Bare hex requires the explicit legacy key and never falls back to current/other keys. Missing/retired versions and malformed/authentication failures return opaque invalid_credentials; invalid configuration is invalid_auth_config and OS entropy failure is auth_crypto_unavailable. No environment key fallback exists.

Envelope versions are canonical decimal with no signs, whitespace, suffixes, exponent or leading zero except0. This deliberately rejects source parseInt permissiveness. Lowercase even hex, minimum40 decoded bytes and maximum4096 plaintext UTF8 bytes are enforced before unbounded allocation. Empty plaintext is supported by the encryption primitive. Authenticated non-UTF8 plaintext refuses rather than using JavaScript replacement decoding. As with the source TextDecoder, decryption strips exactly one leading UTF8 BOM and preserves subsequent/interior BOMs; encryption preserves the input bytes, so BOM-prefixed plaintext is not a byte-identical encrypt/decrypt round trip. Keyring keys, plaintext and encrypted-value wrappers have no Debug/Clone/Serde; explicit accessors are for trusted persistence/verification only. Owned derived keys and plaintext working/output buffers zeroize on drop, with in-place AEAD and capacity reserved before plaintext copy. Input, dependency internals, compiler/allocator/register/OS copies are outside erasure claims.

The existing envelope authenticates ciphertext but not its version header, workspace, user or purpose: empty additional data is a compatibility requirement. Never treat decryption as row ownership or authorization; actual current control identity and keyring/workspace binding remain runtime duties. Reused secret material across versions does not give cryptographic header binding. Runtime rotation must retain necessary historical keys until explicitly qualified migration/re-enrollment, then retire them; no database rewriting or silent rekeying occurs here.

TOTP is HMAC-SHA1 over the eight-byte unsigned big-endian counter floor(unix_milliseconds/30000), using the secret STRING's UTF8 bytes directly; do not base32-decode it. Provisioning's base32 wraps those original bytes. Dynamic truncation modulo1000000 produces exactly six ASCII digits. Verify all three counters[-1,0,+1] around a trusted runtime Clock without early successful return, with constant-time fixed-length code comparisons; return the highest matching counter for future durable replay enforcement. Code must be exactly six ASCII digits; secret1–1024 UTF8 bytes; clock0 through9999-12-31T23:59:59.999Z. Negative/unavailable clock refuses invalid_auth_clock. A negative neighboring counter at the epoch is skipped rather than wrapping to2^64-1 as JavaScript DataView permits. Other malformed inputs return invalid_credentials. This match is not one-time consumption, challenge expiry/attempt budgets/account lockout, current enrollment or session authorization: those require a held control transaction and persistent lifecycle state.

Enrollment secret generation produces32 characters uniformly from the existing64-character ASCII alphabet using OS entropy, yielding192 random bits. No fixed seed, environment source or caller nonce/counter is available in production issuance. Deterministic nonces/counters are test-only helpers. Native TOTP verifier takes a trusted Clock, never a caller/request time claim. No SHA1 signing/security protocol is introduced beyond the existing RFC4226/6238 HMAC OTP profile.

Acceptance: independent libsodium XChaCha vectors (synthetic keys/plaintexts/nonce) and Python stdlib RFC4226/6238 HMAC vectors; native and installed Better Auth random encryption/decryption both directions; current/historical/legacy/retired key cases, exact format/configuration and bounds, key derivation salt-string correction, tag/nonce/ciphertext corruption, Unicode/NUL/empty payloads and authenticated invalid UTF8. Compare native OTP with independently calculated counters and actual installed createOTP using a controlled test clock, including boundaries, future/past windows, wrong code, grammar, secret and clock limits. Preserve secret-free process evidence and native existing password/cookie/login checks. Review and fix concrete findings before delivery. Stop at verified runtime crypto; actual pending challenge/MFA/session/recovery/endpoint, physical SQLite-handle/lifetime admission, cross-platform storage and complete R04/R41/cutover stay pending.

Primary references: https://docs.rs/chacha20poly1305/0.10.1/chacha20poly1305/ ; https://www.rfc-editor.org/rfc/rfc4226 ; https://www.rfc-editor.org/rfc/rfc6238 . RustCrypto's constant-time claim depends on constant-time integer multiplication on the target; this increment verifies the current macOS ARM64 host, not every platform or hardware fault mode.
