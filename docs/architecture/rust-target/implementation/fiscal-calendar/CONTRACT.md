# Typed fiscal calendar for the shared engine

R09 supplies pure canonical Date, fiscal start month and label strategy values plus fiscalYearForDate/annualReportDeadline calendar arithmetic. Native dates are exact ASCII YYYY-MM-DD, proleptic Gregorian years0000–9999; no trim, rollover or 1900 remapping. Reuse the existing engine Gregorian validator. Reject invalid dates, invalid start-month construction and derived fiscal/deadline bounds outside the supported years. Preserve all12 legitimate start months and all three strategies (start-year, end-year, span); span for January is one year. Start/end date strings and year labels are padded to four digits; span suffix is two digits and identifier replaces slash with hyphen. Calendar semantics remain independent of timezone/environment/current time.

Annual-report deadline here means the existing six-calendar-month calculation only: preserve end-of-month or clamp the original day to the destination month's last day. It does not decide company applicability, legal exceptions, rule version, filing status or actual submission. Company configuration adapters must continue resolving legacy defaults/normalization before constructing native typed inputs; raw invalid start months/unknown strategies are explicitly refused by typed native construction rather than silently becoming configuration defaults.

Do not copy known TypeScript defects: fiscal year strings/labels lose padding below1000, Date.UTC maps0–99 to1900–1999, and derived years outside9999 can emit malformed extended-year slices. Keep actual observed source outputs alongside independently fixed native expectations. Exact ordinary-input parity is tested separately from those corrections and typed input refusals. No persisted number, fiscal label, deadline, history or production data is rewritten; existing HTTP trial-balance selection/correction obligations remain owned by R32/R42.

Acceptance: native fixed expectations cover leap/nonleap centuries, year0000/0099, fiscal start/end boundaries, all labels, month-end and ordinary-day six-month behavior, invalid lexical/date/month/strategy inputs and range under/overflow. An independently generated Python-standard-library calendar corpus covers every start month/strategy across month boundaries, modern/century/low/max years and six-month deadlines. Run each case through native engine serialization and actual existing TS helpers; ordinary cases must match exactly, differing/error cases must be explicitly classified and recorded, never normalized away. Retain pure dependency/I/O boundary checks, previous regression suites, scoped GDD readiness, source-bound evidence and independent review. Completion of this scope does not close R09, R12 or the epic, nor enable a writer, clock API, report selection, legal eligibility, UI migration or cutover.
