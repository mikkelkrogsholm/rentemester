# Cooperative workspace process lease

This bounded R12/R43 foundation supplies a Rust runtime lease on an existing physical root directory. It is not a writable runtime, company authorization, IPC discovery or legacy takeover. Existing TypeScript entrypoints are not yet participants. No live adoption, production migration, ledger/config/file writes, or whole-issue completion is authorized by acquiring it. The only executable consumer in this increment is a development example used by process acceptance tests; existing product CLI/API/MCP behavior is unchanged.

Input is an explicit existing nonempty directory path. Reject parent components, missing/non-directory roots and final symlinks including trailing slash/dot aliases. Relative paths are bound to the acquisition working directory once. Ancestor aliases resolve to the same physical inode and therefore the same lock; this local OS capability is not a hosted path authorization mechanism. Do not create or repair a root/lock/metadata file. macOS/Linux use safe rustix directory opens with RDONLY, DIRECTORY, NOFOLLOW and CLOEXEC; other platforms explicitly refuse.

Acquire a nonblocking exclusive flock on that directory descriptor. A competing cooperative opener of the same physical root gets workspace_busy, even in the same process. There is no timeout, PID test, forced takeover, lock-file deletion or alternate writer fallback. Keep the descriptor private, non-Clone and alive until all future protected work/connections have drained; normal Drop/process death releases kernel ownership. A hung process still owns the lease. CLOEXEC prevents an exec child from unintentionally retaining it; raw fork inheritance requires separate qualification and must not be assumed safe.

Check the root filesystem before admission: only the explicitly enumerated local filesystem families in the implementation are candidates. Reject unknown/network families. This check cannot certify absence of background synchronization, mount deception or every filesystem implementation; production qualification must additionally establish same-host, stable, unsynchronized local storage. No distributed/NFS/SMB/cloud-sync safety is claimed. Actual execution in this increment qualifies only the development host/filesystem recorded in evidence.

Identity is the directory descriptor's device/inode pair, with string-safe diagnostic serialization in the development example. Before returning acquisition and on each explicit ensure_current_root call, compare the still-held directory descriptor with a fresh no-follow open of the bound path. Missing, moved or replaced root invalidates that lease permanently; returning the old root to the pathname cannot revive it. Retain the old descriptor/lock until Drop. These checks observe namespace identity; they are not an atomic security fence against a local OS actor swapping paths between checks. Future protected file/storage work must use descriptor-relative operations and its own admission/commit fence, not re-open arbitrary absolute paths after one check.

Errors are typed: invalid_root for invalid lexical/unsupported root input; workspace_unavailable for missing/unsafe/inaccessible root; workspace_busy for kernel contention; unsupported_filesystem for an unqualified family; unsupported_platform for non-macOS/Linux; ownership_io for unexpected kernel/stat failure; workspace_changed for identity loss. No partial lease is returned on failure. The library does not expose the raw descriptor, PID, credentials or a method to forge/upgrade company write authority.

No persistent lockfile is used: adding, deleting or replacing arbitrary PID/IPC/lock metadata cannot change a held directory lock. Removing/replacing the physical root changes its identity and is refused by the old lease's guard. An independently created directory is a different physical scope, not proof of the same logical workspace; stable logical workspace identity, clone/restore lineage, adoption and destination/multi-scope locking remain mandatory before writers. This API cannot detect or stop already-open/unpatched legacy code that ignores flock.

Acceptance: real distinct processes and same-process attempts exclude each other; normal release, EOF and forced process death free the lock; hung-owner/PID metadata changes do not permit takeover; different roots remain independent; lexical/symlink/file/missing roots refuse without creation; aliases share identity; root move/replacement permanently invalidates the old lease; an unrelated ordinary directory open/read/close does not release it; exec children do not inherit it. A cooperative TypeScript/Python participant must contend with Rust using the same kernel protocol, but it must not be presented as current product legacy-ingress coverage. Source tree file-name/hash inventories remain unchanged. Check all child exits and reap all test processes. Full Rust checks and independent implementation review must pass.

The R12 exit gate remains larger: enroll every legacy mutation before its first effect, fence retained handles/jobs/restore/config/auth, bind company paths to actual workspace scope, qualify all supported platforms/filesystems and IPC, and perform offline adoption proving old writers stopped. Acquiring this cooperative lease alone must never enable Rust accounting writes.
