# Native existing-password cryptography

Outcome: replace the installed Better Auth password crypto primitive with native Rust issuance and verification, preserving canonical existing credentials without a Bun/Node runtime. This is R04/R41 cryptography only, not a login endpoint, account lookup, email/MFA/session/reset/recovery/enrollment flow or live credential migration. No DB or filesystem mutation occurs. SQLite opened-handle admission and every existing writer/cutover gate remain pending.

The installed Better Auth1.7.1 delegates to @better-auth/utils0.4.2. Bun1.4.0 selects its node:crypto implementation and uses Unicode17.0/ICU78.1. Exact scheme: NFKC password normalization, scrypt N=16384/r=16/p=1/dkLen=64, with the32-character lowercase hex SALT STRING's UTF8/ASCII bytes as salt, NOT decoded16-byte entropy. Canonical stored format is32 lowercase hex salt characters, one colon,128 lowercase hex derived-key characters (161 bytes total). Native issuance obtains16 fresh bytes from OS getrandom and returns that existing format. No weak RNG, environment salt, caller-selected KDF parameters or fallback algorithm is available.

Use maintained RustCrypto scrypt, Unicode17 normalization (unicode-normalization pinned exactly0.1.25;0.1.26 already uses Unicode18 and is incompatible with the current Bun profile) and constant-time tag comparison. Runtime's hash value is neither Debug, Clone nor serializable; only an explicit as_str accessor allows trusted persistence. Intermediate normalized password and key buffers are zeroized on Drop; caller-owned input and dependency internals are outside that erasure claim. Never log passwords/hashes or embed them in errors. Fixed error codes are invalid_credentials and auth_crypto_unavailable. No new password policy is invented: this low-level primitive accepts empty/short source-compatible passwords; actual enrollment retains Rentemester's12-character minimum and supported endpoint rules when integrated.

Bound input password to4096 UTF8 bytes and normalized output to16384 bytes, before KDF admission. Reject invalid Rust/JSON Unicode input rather than JS lone-surrogate replacement. Verify canonical hashes only; unlike the legacy split(':') helper, ignore no trailing fields, do not coerce malformed representations and never accept noncanonical salt spelling. Wrong passwords, absent credentials and malformed stored hashes return the same invalid_credentials error. Within input bounds, absent/malformed hashes still run one fixed-cost dummy KDF under a fixed noncredential salt, then always refuse. Constant-time final key comparison and equal KDF parameters do not prove wall-clock nonenumeration across future DB/HTTP paths.

The synchronous primitive uses a fixed approximately32MiB scrypt working set per invocation. A future login runtime must dispatch on a bounded blocking worker pool, apply per-source/account/global rate/concurrency limits and generic account errors before exposing it; this function is not an async or DoS-resistant endpoint. Runtime memory exhaustion is not claimed as a recoverable typed error. Entropy/KDF configuration failures have opaque errors. Authentication/MFA and actual authorization still require current locked control rows and native identity lifecycle.

Acceptance: independent Python hashlib.scrypt vectors freeze salt-string use, NFKC, whitespace/NUL/Unicode and wrong-password cases; installed framework verifies native-issued hashes and native verifies actual framework-issued hashes. Full unmodified Unicode17 NormalizationTest vectors exercise all five NFKC input columns in Rust and current Bun, with original license and source hash retained; independent Rust/Bun SHA256 transcripts also compare NFKC for every1,112,064 Unicode scalar, including currently unassigned characters; normalization is not inferred from a handful of examples. Test canonical/malformed/extra-field/oversize refusals, dummy-KDF selection, fresh OS entropy and secret-free diagnostics. Existing cookie/layout/access and native checks remain green. No scheme strength upgrade, password rewrite, PHC/new format, production credential copying, policy bypass or complete R41/R55 acceptance is claimed.

The old161-byte format does not record its issuing Unicode version. Compatibility with the installed Unicode17 runtime does not prove every historical credential was issued under that profile. Historical runtime inventory and explicit mapping or re-enrollment remain a credential-migration gate; never guess or silently retry alternate normalization versions. Unsupported normalization histories do not permit a new accounting/principal identity or replay scope.
