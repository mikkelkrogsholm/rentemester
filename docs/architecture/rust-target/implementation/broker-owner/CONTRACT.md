# Persistent broker ownership prerequisite

Outcome: a persistent owning runtime must acquire a protected namespace and retain it until every SQLite connection has explicitly closed. Linux dedicated UID is the first server profile; macOS local desktop remains required and is not replaced by remote-only operation. Qualification uses synthetic files only. No existing user workspace adoption or production writer is authorized by this prerequisite.

Trusted deployment supplies an absolute workspace root, exact workspace/company selection and a nonzero broker UID. The executing Linux thread must have that real/effective/saved/filesystem UID, no permitted/effective/inheritable/ambient/bounding capabilities, NoNewPrivs=1 and umask0077. Launcher/installer sets these before threads, with each operation checking /proc/thread-self/status rather than the thread-group leader; the library does not change process privileges or permissions. Root/operator and enrolled broker-UID code are trusted; normal clients and legacy tools run a different unprivileged UID. Same-UID malicious processes are not isolated by Unix file modes.

Walk every absolute ancestor with DIRECTORY/NOFOLLOW/CLOEXEC. Ancestors must be root- or broker-owned and not group/world writable; the workspace root and its internal directories require broker ownership and mode0700. Regular manifest/control/ledger files require broker ownership, mode0600, one link and root-device identity. Reject access/default POSIX ACL attributes or inability to establish absence. Known WAL/SHM/journal names are absent or regular single-link broker0600 files. Refuse unsafe metadata before opening regular files; no chmod/chown/unlink/repair occurs. Hold the cooperative root lease and descriptor-bound layout. Live validation uses only directory opens and statat/xattr/read_at/fstat for regular entries, never an ordinary main/sidecar/manifest inode open/close. All namespace/restore/archive/capture actions must obey the owning lifetime protocol.

The forthcoming host owns private connections and uses fixed typed operations that call the existing application code. No public mutable connection callbacks/accessors or connection-bearing outputs are permitted. Bind layout before SQLite opens. Explicit close failure retains the returned connection and the entire layout/lease; retired owners accept no further work. Drop must retain/quarantine unresolved resources until process exit, rather than trusting rusqlite's best-effort destructor or releasing pinned descriptors prematurely. Construction failures and panics need the same discipline.

Acceptance must include actual Linux separate-UID read/write/rename denial, unsafe mode/UID/ACL/sidecar refusals, same-UID negative controls, real WAL/DELETE locks, confirmed-close/BUSY and partial-construction/crash cases on synthetic persistent files. Existing macOS observation tests remain valid but do not qualify this Linux deployment profile. A passing namespace slice alone is not a completed owning runtime, fresh initialization/bootstrap, HTTP/CLI/MCP composition or complete R12/epic acceptance.

File modes deny new different-UID path access. They cannot revoke a previously opened or inherited/passed descriptor. Fresh protected provisioning, no client descriptor inheritance/SCM_RIGHTS handoff and offline migration/drain are required admission conditions; no file-descriptor scan or chmod-based live takeover is claimed. Existing native reopen must retain that provisioning lineage. These conditions still need enforcement by the owning host and initializer.

Current namespace implementation is qualified by a self-contained Docker source-only driver: 41 checks, including 132 actual different-UID denials, real access/default ACL installation and read-back, same-UID/permissive positive controls, actual worker/leader NoNewPrivs divergence, prior-FD survival, WAL/DELETE lease and lock preservation, sticky retirement and explicit clean reopen. Its named volume reports the Linux ext family; a tmpfs returning EOPNOTSUPP for ACL queries is refused rather than treated as ACL-free. These candidate results do not establish disk power-loss or deployment qualification. A privileged fake-WAL negative control changes the second SQLite process to a different WAL/SHM lock protocol while raw fcntl confirms the first process's original main POSIX locks remain held. Root/operator remains trusted. Confirmed-close/BUSY quarantine, private typed host dispatch, initialization/bootstrap and all real legacy/transport flows remain unimplemented gates.
