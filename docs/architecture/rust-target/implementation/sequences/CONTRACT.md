# Transactional sequence allocation

R12 needs one sequence primitive before journal/invoice posting. Port current/next/reserve behavior from src/core/sequences.ts to rentemester-storage using exact nonnegative signed64-bit SQLite INTEGER values. Scope is explicit (kind, scope); preserve all text, including empty/NUL/Unicode. Company scope composition consumes already-normalized trusted company CVR and follows nullish fallback to company-ID. Raw CVR normalization belongs to company-settings admission (legacy getCompanySettings calls normalizeCvr, including empty→NULL and DK prefix); it is not duplicated in this primitive. Fiscal date/suffix discovery and invoice/journal number formatting remain domain caller responsibilities. Existing TypeScript valid safe-integer behavior is the independent compatibility oracle; exact full-width Rust integers are tested against SQLite, not claimed equivalent to rounded JavaScript Numbers.

Expose current as an advisory read on an existing connection: max(stored-or-zero, floor). Require next/reserve to borrow an existing rusqlite Transaction whose main database is already in Write state (BEGIN IMMEDIATE or earlier successful write). Refuse a deferred/read-only transaction before changing a row. The caller owns admission, lock lifetime, authorization, schema validation, busy policy and commit/rollback; the primitive opens no paths, creates no schema and grants no writer authority. No Rust product mutation command is enabled.

next computes max(stored-or-zero, floor)+1, inserts or updates the exact INTEGER, and returns it. reserve returns {ok,current_value,expected_value}; only requested==current+1 writes that value. A mismatch writes nothing. Independent kinds/scopes stay independent. Negative floor/request inputs refuse invalid_input, non-INTEGER/negative stored values refuse invalid_ledger, and exhaustion at i64::MAX refuses sequence_exhausted before SQL arithmetic could promote to REAL. SQL failures return sanitized storage_failure. Every error requires the owning caller to abort its transaction; success still requires caller commit. Later business failure or process death must roll back sequence allocation and companion business rows together. Never commit a business reservation on its own inside this primitive.

Acceptance: independent actual TS operation vectors cover absent/current/floor jumps/lower floors/manual mismatch/accepted reservation/separate scopes and company CVR fallback, plus outer rollback. Native tests use actual company schema/immutable sequence guards, exact full-width/max values, invalid stored types, deferred refusal and forced SQL failure. Separate SQLite connections/processes race automatic allocations and the same requested reservation under an immediate write transaction, yielding unique committed values or one winner respectively, with no snapshot upgrade race. Kill/reap a process after allocating and adding a companion row before commit: neither remains and retry starts at the prior committed value. Preserve all previous suites; scoped GDD readiness and independent review must pass. These tests do not qualify live writer admission, idempotency receipts, invoice/journal floors, multi-store authority, hardware power loss, platform distribution, full R12 or epic completion.
