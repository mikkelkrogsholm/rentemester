# R14: Port atomic posting, reversal, idempotency and shared mutation gates

<!-- rentemester-rust-plan:R14 -->

Parent epic: #672. Phase: P2 — Durability, authority and atomic writes. Status: planned.

## Outcome

Provide the single authoritative write pipeline used by all interfaces.

## Scope

- Port dry-run/post/reverse with actor, confirm, period, evidence, backup and rule gates

- Commit journal, audit chain, sequences and scoped idempotency receipt together

- Preserve expiry/tombstone/replay behavior and exact refusal taxonomy; compose later VAT/domain validators before their features are enabled

## Dependencies

- Requires #681 — Implement exact accounting value types and invariant evaluation

- Requires #684 — Implement workspace ownership, transactional storage and safe migrations

- Requires #685 — Port workspace/company authorization and revocation fencing

- Requires #686 — Port immutable document storage, safe ingestion and evidence access

## Acceptance criteria

- [ ] Crash between every write rolls back all business-success state; reversal appends rather than edits

- [ ] Concurrent same-key calls return one receipt; changed payload conflicts; revoked replays reveal no protected result

- [ ] Closed period, missing confirmation, invalid evidence and backup-lock denial leave no partial posting

## Verification and completion

Attach actual revision-bound checks for the criteria above, including the stated refusal/failure paths. Refine typed contracts, risk/error scenarios and data effects before implementation; the planning graph is a sketch, not proof of readiness or behavior. Record any unsupported environment or external dependency as a blocker rather than lowering acceptance.

## Boundaries

No live migration or unrelated new product capabilities. One authoritative writer per workspace; company-specific data stays in workspace configuration; checked-in acceptance data is synthetic. Preserve existing accounting/security/release gates. No live use before the cutover gate.
