Parent epic: #672. Phase: P4 — Providers, identity and runtime. Status: planned.

## Outcome

Deliver the selected identity design with browser/native/agent parity and a path off Better Auth.

## Scope

- Implement supported browser/native auth, sessions, MFA/recovery/reset/invites and redacted auth audit

- Port service-account credential create/rotate/revoke/reconcile and one-time secret delivery

- Implement credential/account migration or explicit re-enrollment without copying insecure state

- Requires #676 — Resolve hosted/native identity and cross-database authorization ordering

- Requires #677 — Specify versioned API, typed failures and capability negotiation

- Requires #685 — Port workspace/company authorization and revocation fencing

- Requires #690 — Implement durable jobs, external effects and restart recovery

## Acceptance criteria

- [ ] Revocation, recovery replay, CSRF/origin, rate-limit and concurrent owner/service-credential scenarios pass

- [ ] Native auth binds exact server/account, handles cancellation and stores secrets in OS facilities

- [ ] Temporary Better Auth bridge cannot satisfy retirement; final runtime identity path needs no Bun/Node/TypeScript service

- [ ] Credential rotation/re-enrollment and local↔hosted move preserve or explicitly map stable accounting/replay identities: accepted writes with lost replies are never replayed as new writes; unauthorized old receipts remain inaccessible.

- [ ] Revoked human/service credentials cannot authorize newly dispatched jobs contrary to R04; in-flight results remain auditable and reconcilable.
