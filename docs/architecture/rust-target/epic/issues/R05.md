## Outcome

Give React browser/embedded desktop, CLI and MCP one explicit transport contract for compatibility and uncertain writes.

## Scope

- Specify OpenAPI/JSON-schema or equivalent versioned request/response contracts, exact amounts and binary/file routes

- Define limits, pagination/filter ordering, errors, idempotency/revision/confirm semantics and capabilities

- Document auth-required discovery versus public build/protocol metadata and compatibility windows

- Produce an operation-by-operation retry matrix: key support/scope/TTL/tombstone, natural dedup, authoritative read-back and unresolved provider outcome; adding key support is an explicit versioned implementation change.

- Record exact CLI versus MCP versus HTTP success/error schema mappings; retain existing intentionally distinct envelopes, arrays, field casing and SDK errors through an explicit compatibility policy.

## Dependencies

- Requires #673 — Freeze the migration baseline and complete the feature/contract inventory

- Requires #675 — Define exact money, schema, audit and wire compatibility

## Acceptance criteria

- [ ] Old React clients have an explicit supported compatibility path; no numeric-wire breaking change is silent

- [ ] Unknown capabilities/incompatible protocol refuse dependent actions before mutation

- [ ] Lost response, malformed binary error, revoked session and cancelled reads have explicit safe client outcomes

- [ ] Every advertised operation has an exact input/success/refusal/parse-protocol schema and a retry class; generic original-key recovery is never promised for unsupported operations.

## Verification and completion

Attach actual revision-bound checks for the criteria above, including the stated refusal/failure paths. Refine typed contracts, risk/error scenarios and data effects before implementation; the planning graph is a sketch, not proof of readiness or behavior. Record any unsupported environment or external dependency as a blocker rather than lowering acceptance.

## Boundaries

No live migration or unrelated new product capabilities. One authoritative writer per workspace; company-specific data stays in workspace configuration; checked-in acceptance data is synthetic. Preserve existing accounting/security/release gates. No live use before the cutover gate.
