## Named owner acceptance scenarios

### J01 — Fresh local owner, VAT company

Given: Fresh qualified machine, no Bun/Node/Docker, synthetic VAT-registered company.

When: Install, choose data directory, configure identity/fiscal/VAT/account plan/bank, ingest receipt, review/post, inspect report and verify/export backup.

Then: Owner completes normal setup/accounting without JSON/CLI, exact report/evidence links and off-device recovery instructions are visible.

### J02 — Existing business, no VAT and shifted year

Given: Supported synthetic imported business, non-VAT configuration, shifted fiscal year and opening balances.

When: Import/restore with explicit mapping, review open items, post first expense and inspect period/report/backup.

Then: No invented VAT or duplicate opening balances; unresolved historical evidence blocks correctly and the owner gets the next action.

### J03 — Remote multi-user operation and access loss

Given: Hosted workspace, two companies, owner/bookkeeper/service identities.

When: Log in web/native, switch company, review/post, revoke access during a pending read/write.

Then: Same authoritative ledger, visible server/company and role-correct actions; no cross-company/stale-cache disclosure or local fallback.

### J04 — VAT/annual task state and required user action

Given: A synthetic period with VAT source evidence and an unresolved blocker.

When: Review basis, resolve blocker, prepare/lock/record filing as actually supported.

Then: UI distinguishes draft/reviewed/recorded from submission, shows sources/deadline rules and the next manual action without false filing claims.

### J05 — Lost computer and verified owner recovery

Given: Separately held verified backup and trust material, then source device unavailable.

When: On a fresh device restore to a fresh directory; re-provision secrets and inspect bank/evidence/journal.

Then: Exact supported inventory/audit restores, missing destination/key produces actionable help, owner/operator responsibilities are explicit.

### J06 — Local-to-server and server-to-local handoff

Given: A supported synthetic workspace with an accepted write whose response was lost, plus pending/ambiguous external effects.

When: Stop/fence source, verify transfer, map identity/receipts, activate destination, retry original operation and reopen old source.

Then: One writer/dispatcher, no duplicate booking/delivery, replay obeys access policy; owner sees destination and moved/read-only source.

### J07 — Local closure/sleep versus hosted automation

Given: Explicitly enabled supported recurring/intake/backup tasks in local and hosted profiles.

When: Close app/sleep/change timezone or DST, then restart; revoke/cancel a queued task.

Then: Documented catch-up/skip and dispatch-authority policy, last/next/missed/pause/error visible, no implied unattended local service.
