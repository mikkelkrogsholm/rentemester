# R35: Implement durable jobs, external effects and restart recovery

<!-- rentemester-rust-plan:R35 -->

Parent epic: #672. Phase: P4 — Providers, identity and runtime. Status: planned.

## Outcome

Provide recoverable external delivery/scheduling without claiming cross-provider exactly-once transactions.

## Scope

- Implement committed effect records, job state/leases, bounded retry/backoff and reconciliation

- Define schema upgrades, cancellation, lease expiry and process-crash recovery

- Expose task status/read-back with redacted logs and explicit caller authorization

- Implement R04 dispatch authority/revocation policy; explicitly define local-versus-hosted scheduler activation, timezone/DST, sleep, shutdown/restart, missed-occurrence catch-up/skip and cancellation semantics.

## Dependencies

- Requires #684 — Implement workspace ownership, transactional storage and safe migrations

- Requires #685 — Port workspace/company authorization and revocation fencing

- Requires #687 — Port atomic posting, reversal, idempotency and shared mutation gates

## Acceptance criteria

- [ ] Crash before/after provider acceptance and lease expiry cannot silently double-deliver or lose committed work

- [ ] Ambiguous outcomes remain visible for reconciliation; provider capability controls safe retry

- [ ] Read-only inspection never performs network effects or starts a scheduler implicitly

- [ ] Revoke/cancel before dispatch, in-flight provider calls and restore of committed jobs follow the documented authority order.

- [ ] Local app shutdown stops its managed worker; no unattended service is implied. Reopening shows missed/paused/failed/last/next runs and uses the chosen explicit catch-up policy without duplicates.
