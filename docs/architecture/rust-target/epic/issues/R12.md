# R12: Implement workspace ownership, transactional storage and safe migrations

<!-- rentemester-rust-plan:R12 -->

Parent epic: #672. Phase: P2 — Durability, authority and atomic writes. Status: planned.

## Outcome

Establish one writable runtime and verifiable schema changes before domain mutation work.

## Scope

- Implement workspace ownership/IPC discovery, busy handling and verified stale-owner recovery

- Port company/control migrations, checksums, append-only guards, sequence allocation and transaction primitives

- Define lock ordering, crash/fsync semantics and read/write coexistence; refuse simultaneous legacy/Rust writers

## Dependencies

- Requires #675 — Define exact money, schema, audit and wire compatibility

- Requires #679 — Bootstrap the Rust workspace, build tooling and architecture checks

## Acceptance criteria

- [ ] Two runtime processes cannot acquire one workspace; PID reuse and stale/missing lock cases do not permit unsafe takeover

- [ ] Migration failure/crash leaves a recoverable old or fully migrated schema with no half-applied state

- [ ] Unsupported downgrade, tampered migration and direct UPDATE/DELETE against immutable records fail

## Verification and completion

Attach actual revision-bound checks for the criteria above, including the stated refusal/failure paths. Refine typed contracts, risk/error scenarios and data effects before implementation; the planning graph is a sketch, not proof of readiness or behavior. Record any unsupported environment or external dependency as a blocker rather than lowering acceptance.

## Boundaries

No live migration or unrelated new product capabilities. One authoritative writer per workspace; company-specific data stays in workspace configuration; checked-in acceptance data is synthetic. Preserve existing accounting/security/release gates. No live use before the cutover gate.
