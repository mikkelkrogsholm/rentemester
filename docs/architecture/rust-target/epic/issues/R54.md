## Acceptance criteria

- [ ] Source/target processes cannot write simultaneously, including restored jobs/effects and older clients

- [ ] Injected corrupt snapshot, wrong identity, migration failure and activation crash leave a known recoverable authority

- [ ] Post-cutover rollback does not discard accepted new entries or reopen incompatible data; runbook states recovery point/time from measured rehearsals

- [ ] Credential rotation/re-enrollment and local↔hosted move preserve or explicitly map stable accounting/replay identities: accepted writes with lost replies are never replayed as new writes; unauthorized old receipts remain inaccessible.

- [ ] J06 shows source, destination, stop, verification and activation clearly; source tombstone/fencing survives reboot and copied configuration while immutable archived data remains readable.

- [ ] Restored pending external effects are fenced from source dispatch; completed/ambiguous outcomes remain reconciled and cannot be blindly redelivered.

Given: A supported synthetic workspace with an accepted write whose response was lost, plus pending/ambiguous external effects.

When: Stop/fence source, verify transfer, map identity/receipts, activate destination, retry original operation and reopen old source.

Then: One writer/dispatcher, no duplicate booking/delivery, replay obeys access policy; owner sees destination and moved/read-only source.
