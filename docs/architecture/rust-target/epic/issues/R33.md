## Acceptance criteria

- [ ] Tampered signature, missing file, path traversal, wrong target and missing confirmation refuse before publication

- [ ] Restore to a fresh destination passes inventory/audit/state parity; retry never silently overwrites live data

- [ ] Local-to-hosted and hosted-to-local restore re-provisions identity/secrets explicitly; remote placements preserve actual provider/region evidence

- [ ] Loss of the computer can be recovered on a fresh machine from a separately held verified backup and required trust material; backup on the lost disk alone is not counted as recovery.

- [ ] Missing destination access or trust material produces clear recovery instructions; UI distinguishes self-service owner tasks from server-operator tasks.

## Named owner acceptance scenarios

### J05 — Lost computer and verified owner recovery

Given: Separately held verified backup and trust material, then source device unavailable.

When: On a fresh device restore to a fresh directory; re-provision secrets and inspect bank/evidence/journal.

Then: Exact supported inventory/audit restores, missing destination/key produces actionable help, owner/operator responsibilities are explicit.

### J06 — Local-to-server and server-to-local handoff

Given: A supported synthetic workspace with an accepted write whose response was lost, plus pending/ambiguous external effects.

When: Stop/fence source, verify transfer, map identity/receipts, activate destination, retry original operation and reopen old source.

Then: One writer/dispatcher, no duplicate booking/delivery, replay obeys access policy; owner sees destination and moved/read-only source.
